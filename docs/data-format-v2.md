# DataLocal 2.0 Data Format

Status: Draft  
Format identifier: `datalocal/2`

## Requirements

The format must be:

- versioned
- deterministic before encryption
- authenticated after encryption
- recoverable after interrupted writes
- independent of SharedPreferences
- extensible for future storage adapters
- migratable without deleting the source first

## Logical record

```json
{
  "format": "datalocal/2",
  "collection": "notes",
  "id": "opaque-id",
  "revision": 1,
  "createdAtUs": 1750000000000000,
  "updatedAtUs": 1750000000000000,
  "codec": "json/1",
  "schemaVersion": 1,
  "data": {
    "title": "Example",
    "completed": false
  }
}
```

Timestamps are UTC microseconds since Unix epoch. Storage adapters may use a
binary encoding internally, but decoding must yield the same logical record.

## Encrypted envelope

The serialized logical record is encrypted as one authenticated message.

```json
{
  "format": "datalocal-envelope/1",
  "algorithm": "AES-256-GCM",
  "keyId": "installation-key-1",
  "nonce": "<base64url>",
  "ciphertext": "<base64url>",
  "mac": "<base64url>"
}
```

Binary storage may use a compact representation. JSON is shown for readability,
not mandated as the final wire encoding.

Authenticated associated data contains:

```text
format
database name
collection name
document ID
schema version
```

Moving an encrypted record to another database, collection, or document ID must
fail authentication.

## Key rules

- AES key length is 256 bits.
- Nonces are generated by a cryptographically secure random source.
- A key and nonce pair is never reused.
- `keyId` identifies a key without containing key material.
- Rotation writes new records with the active key.
- Existing records may be re-encrypted incrementally.
- Missing and revoked keys produce explicit exceptions.

## SharedPreferences namespace

```text
datalocal.v2.<database-token>.database
datalocal.v2.<database-token>.collection.<collection-token>
datalocal.v2.<database-token>.record.<collection-token>.<id-token>
datalocal.v2.<database-token>.journal
datalocal.v2.<database-token>.migration
```

Tokens are encoded so arbitrary user names cannot collide with separators.
Raw database and collection names must not be used as unescaped preference keys.

## Database manifest

The database manifest contains:

- format version
- database identity
- collection tokens
- active encryption key ID
- last committed transaction sequence
- migration state

It does not duplicate complete document payloads.

## Collection manifest

The collection manifest contains:

- collection identity
- schema version
- document IDs or manifest chunk references
- collection revision
- record count

If size limits require chunks, chunk membership is immutable within a commit and
updated through the journal.

## Journal

Journal states:

```text
prepared
applying
committed
```

A journal entry includes:

- transaction ID
- previous database sequence
- target database sequence
- affected record keys
- before/after checksums or recovery references
- state

Recovery policy:

- `prepared`: discard staged values.
- `applying`: restore the last committed state or complete a verified replay.
- `committed`: clean temporary values.

No observer sees an uncommitted transaction.

## Integrity

Encrypted records rely on the AEAD authentication tag. Unencrypted mode includes
a non-security checksum to detect accidental corruption.

Checksums are not presented as protection against malicious modification.

## Legacy format

The 1.x decoder is read-only. It:

- understands the historical preference key derivation
- understands the historical encrypted payload
- converts legacy metadata into the v2 metadata model
- records undecodable IDs in the migration report

New writes never use the legacy cipher or key.

## Compatibility

- Patch releases may add optional fields.
- Minor releases may add understood format capabilities.
- A format-breaking change requires a migration and a new format identifier.
- Unknown required capabilities cause an explicit unsupported-format exception.
- Unknown optional fields are preserved where practical.
